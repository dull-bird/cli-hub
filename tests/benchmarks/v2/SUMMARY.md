## 📝 Qualitative Analysis

### Key Finding: Tool Discovery Behavior

**WITH cli-hub:** The model consistently uses the `cli-hub` skill to look up unfamiliar tools:
- A1: Model invokes `cli-hub` → `lookup mmx` to discover what the tool is
- A6: Model invokes `cli-hub` → `opencli --help` to understand the tool
- 7/8 tests show explicit cli-hub usage (Skill calls, registry lookups)

**WITHOUT cli-hub:** The model does NOT know what the tools are:
- A1: Model says "我不太确定你指的 mmx 是什么" (I don't know what mmx is)
- A6: Model hallucinates `opencli server-info list-site-adapters` (wrong subcommand)
- A8: Model claims "环境中没有安装 opencli" (opencli not installed) when it IS installed;
  falls back to `curl` + Bilibili API directly — works but misses the tool

### Key Finding: Output Conciseness

WITH cli-hub outputs are significantly more concise (avg 697 bytes vs 1881 bytes).
This is because the model, knowing the tool exists via the registry, focuses on
constructing the correct command rather than:
- Explaining what the tool might be
- Asking the user for clarification
- Providing lengthy fallback approaches

### Net Effect

cli-hub transforms the model's behavior from **"I don't know this tool, let me guess/ask"**
to **"Let me look it up in the registry and give you the right command."**
This is the core value proposition of cli-hub as a CLI discovery gateway.
